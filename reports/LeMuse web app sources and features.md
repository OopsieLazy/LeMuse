# Sell the Value Checker, Stream More Museums

Build the value-study web app, but treat it as a small, free-first tool. Greyscale, invert and notan alone are now a free commodity. The one idea people would pay for is **comparing a photo of your painting with your reference on the same numeric value scale**. The web app is more sellable than the desktop app on reach. It shows no SmartScreen warning, it works on the phone at the easel, and it uses only the user's own photos, so no Are.na or museum terms ride on it. The honest revenue picture is still pocket money to a few hundred dollars a month. Rivals charge about **$7–$18 once**, and even 10,000 monthly users converting at 1–3% to an $8 unlock would bring in roughly **$800–$2,400 a month**, a traffic level a new tool may never reach. Build it as a static, no-upload app inside the existing repo, on Cloudflare's free static hosting, served from a subdomain of the friend's domain that points at an account the owner holds. Launch it free with an off-site support link and keep it MIT. Don't use Lemon Squeezy: it stopped taking new sellers on 16 November 2026 and shuts down on 31 March 2027. On imagery, no new source beats SMK and The Met, which are already queued for 1.3. This round adds **iNaturalist** (no key; animals for gesture and creature work), **Auckland Museum** (no key; keyword search) and **Pexels** (only with a key the user brings), and refuses Pixabay, Flickr, social feeds and Unsplash. From competitors, the best-value ideas are keyboard-first and ambient, not AI: an info overlay that shows the attribution, a command palette, breaks in class plans, a seeded weekly pack, an ambient display mode and an OBS stream overlay that no one else ships. These slot into the earlier 1.2/1.3 plan without changing its spine. Two things change: the web app goes right after 1.1, and a new 1.4 "ambient and on stage" release follows 1.3.

## No new source beats SMK and The Met; iNaturalist, Auckland and Pexels fill the gaps

The test for a LeMuse source hasn't changed. One keyword search per topic keyword, one page, weekly. The response must carry openly licensed images on **one fixed image host** that the CSP can allow-list. Hotlinking must be allowed, because LeMuse never caches. And the source needs either no key or a key the user owns, because any key shipped in an MIT binary is public. Measured that way, this round found **no source that beats the earlier top four** (SMK, The Met, Wikimedia Commons and Smithsonian). What it did find is sources that fill subject gaps those four leave: living animals for gesture and creature artists, natural forms for illustrators, everyday photos of people and interiors, and technical drawings for product designers.

**iNaturalist** is the strongest newcomer. It needs no key and carries a licence per photo, and animals in motion are exactly what gesture and creature artists lack in museum collections. Its documented ceiling is "a max of 100 requests per minute", and it asks clients to "keep it to 60 requests per minute or lower" ([iNaturalist forum](https://forum.inaturalist.org/t/discrepancy-between-documented-rate-limit-observed-rate-limit/8612)). One search per keyword per week sits far below that. The catch is image delivery. On its open-data bucket, one image per second "almost instantly hit the rate-limit", and those limits are undocumented ([GitHub issue](https://www.github.com/inaturalist/inaturalist-open-data/issues/5)). The connector should therefore filter to CC0 and CC BY photos, preload only one slide ahead, and wait until the owner has opened a sample image in a normal browser, the check that caught AIC's Cloudflare challenge. **Auckland Museum** is the closest match to the Cleveland connector's shape: its current API "removed the need for an API key" and searches by keyword over plain HTTP ([Auckland Museum API](https://api.aucklandmuseum.com/)). Images are CC BY or "No Known Copyright Restrictions", but some records are CC BY-NC ([Auckland Museum](https://www-learn.aucklandmuseum.com/mi/discover/collections/our-data)), so the connector must filter per record. It also exposes two API bases, and which one is current is unclear. **GBIF** is unusual because many publishers' specimen photos come through **one host** (`api.gbif.org`), at up to 1200×1200 px. GBIF asks scripted users to "limit … to a single HTTP connection", and warns that images "may be licensed under more restrictive terms" ([GBIF image API](https://techdocs.gbif.org/en/openapi/images)). It suits natural-form studies, but it needs per-image licence storage and a preload of one.

The commercial photo APIs split cleanly. **Unsplash** fits LeMuse's design better than any other, because it *requires* hotlinking ([Unsplash guidelines](https://help.unsplash.com/en/articles/2511245-unsplash-api-guidelines)). But its own JavaScript library tells browser apps to proxy requests through a server that holds the key ([unsplash-js](https://github.com/unsplash/unsplash-js)). Its guidelines bar requiring users to register their own developer account, and its "non-automated" wording sits badly with a scheduled weekly refresh ([Unsplash guidelines](https://help.unsplash.com/en/articles/2511245-unsplash-api-guidelines)). The only compliant route is an owner-run proxy, which means a server, a bill and a held secret, so leave Unsplash out. **Pexels** gives any account holder a free key instantly, allows 200 requests an hour and 20,000 a month, and has no hotlinking clause ([Pexels API](https://www.pexels.com/api/documentation/)). It can work the way the Are.na token already does: the user pastes their own key and it lives in Credential Manager. Pexels forbids "making Pexels content available as a wallpaper app" ([Pexels API](https://www.pexels.com/api/documentation/)), so Pexels images must be kept out of any future wallpaper or ambient-display feature. **Pixabay** is incompatible. "Permanent hotlinking of images … is not allowed", and display URLs are "valid for 24 hours" ([Pixabay API](https://pixabay.com/api/docs/)), so every stored link would go stale within a day. **Flickr** issues keys only to Pro subscribers and caps display at "30 Flickr user photos per page" ([Flickr API ToS](https://www.flickr.com/services/api/tos/)).

For product, industrial and CAD designers, **US patent drawings** are the best find on licence grounds. "The text and drawings of a patent are typically not subject to copyright restrictions", with exceptions where an applicant's notice appears ([Penn State LibAnswers](https://psu.libanswers.com/faq/325294)). Design patents of chairs, tools and consumer products are exactly the reference those users want. Nobody has yet researched which USPTO or Google Patents endpoint returns figures as images, so this needs a short research spike before any build. **Sketchfab** search can filter downloadable models by licence slugs, including `cc0` ([Sketchfab license filters](https://sketchfab.com/blogs/community/refine-downloadable-model-searches-with-new-license-filters)). Its thumbnails could become a "3D model previews" source for game and product artists, but the thumbnail host and rate limits are unverified. **The Getty** (about 88,000 CC0 images; [Creative Commons](https://creativecommons.org/2024/03/13/getty-museum-releases-88k-images-of-artworks-with-cc0/)), **Mia** and **Yale** have strong open images but no simple keyword search. Using them would mean building a local metadata index, a bigger design change, so park them. **NYPL** (a `publicDomainOnly` filter, but a token issued by email; [NYPL API](https://api.repo.nypl.org)) and **Te Papa** (registration with name, organisation and email, plus some CC BY-NC-ND items; [Te Papa terms](https://tepapa.govt.nz/api-terms-of-use)) put too much friction on users for now.

Several inputs should be refused outright. Mastodon and Bluesky feeds stream other people's all-rights-reserved posts from many hosts. Google Photos removed its library-read scopes on 31 March 2025, leaving only a user-driven Picker ([Google Developers Blog](https://developers.googleblog.com/en/google-photos-picker-api-launch-and-library-api-updates/)). DPLA serves thumbnails from contributors' hosts, the same CSP problem as Europeana ([DPLA](https://pro.dp.la/developers/api-basics)). David Rumsey's maps are CC BY-NC-SA ([Stanford PURL](https://purl.stanford.edu/xh235dd9059)). Brooklyn caps each key at 3,000 calls a day, and its licence statements conflict ([Brooklyn API](https://www.brooklynmuseum.org/opencollection/api/register)).

## The value app sells modestly, and only with a compare-your-painting hook

The bad news first: basic greyscale, notan and posterise are **free, everywhere, and already private**. ArtistTools.org gives away **70 tools**, including a value checker and a notan generator, with no paid tier at all, because it feeds a course business ([artisttools.org](https://artisttools.org/)). TonalValueTool.com does 2–16 value levels with "all image processing … done locally on your device" and a coffee-tip link ([tonalvaluetool.com](https://tonalvaluetool.com/)). Notana gives every tool away free in a browser extension and charges **$95 a year** for settings sync alone, from "450+ painters" ([usenotana.app](https://usenotana.app/)). ArtistAssistApp is open source under AGPL, works offline, and funds itself through Patreon extras ([GitHub](https://github.com/eugene-khyst/artistassistapp); [Patreon](https://www.patreon.com/artistassistapp)). Its Show HN drew **168 points** ([Hacker News](https://news.ycombinator.com/item?id=38011432)). "No upload, your photo stays private" no longer sets a web tool apart; at least four of these sites make the same claim.

The money is on phones with a live camera. **Value Study** has a **4.8★ rating from 3.4K US ratings**, sells a $23.99 lifetime and a $7.99 yearly Pro, and has built-in tips at $2.99, $9.99 and $24.99 ([App Store](https://apps.apple.com/us/app/value-study/id1546616127)). The developer's own site quotes lower prices, about $1.99 a year or $6.99 lifetime, and says a 2026 update removed the free tier ([valuestudy.app](https://valuestudy.app/llms-full.txt)), so no single figure is firm. **Painting Mirror** charges $17.99 once or $14.99 a year, and is the closest product to "hold your phone over your painting and compare it with the reference" ([App Store](https://apps.apple.com/app/id6769758248)). **ValuePal** is $14.99 up front ([App Store](https://apps.apple.com/af/app/valuepal/id1567093159)). **Color Study** has **4.9★ from 590+ ratings** and puts its value and notan tools behind a Pro subscription ([colorstudy.app](https://colorstudy.app/)). The going rate is roughly **$7–$18 once, or $2–$15 a year**. No public revenue figure exists for any value-study tool.

What users ask for is consistent. They want simplicity ("Just enough features but not so many that it gets confusing"; [Value Study reviews](https://apps.apple.com/us/app/value-study/id1546616127)). They want **stable numbers**: a See Value user asked to "average out the readings over a second's time", and the developer couldn't, so he sent the user to a rival ([App Store](https://apps.apple.com/us/app/see-value/id1312532225)). They want no ads ("better free alternatives… without being crushed by ads"; [App Store](https://apps.apple.com/us/app/id1531149807)). And they already compare their painting with the subject by hand, photographing work in progress and desaturating it on the phone ([WetCanvas](https://www.wetcanvas.com/forums/topic/an-easy-way-to-check-the-values-in-your-painting/)). Even greyscale itself isn't trusted: Photoshop users note that "every single way differs in some way from the other" ([Adobe Community](https://community.adobe.com/t5/photoshop-ecosystem-discussions/so-what-s-the-best-most-accurate-way-to-do-a-grayscale-check-in-photoshop/m-p/13661425)). Artists also respond to an explicit no-AI stance: Procreate's 2024 pledge was widely praised ([TechCrunch](https://techcrunch.com/2024/08/19/procreate-takes-a-stand-against-generative-ai-vows-to-never-incorporate-the-tech-into-its-products)), and ArtistAssistApp sells itself with "Just good old math" ([HN](https://news.ycombinator.com/item?id=38011432)).

**So is the web app more sellable than the desktop app? Yes, but only relatively.** The desktop app is hard to sell for three reasons. First, Windows' Smart App Control blocks unsigned files that lack reputation, and signing costs about $10 a month ([Microsoft Learn](https://learn.microsoft.com/en-us/windows/apps/package-and-deploy/code-signing-options)); even after paying, new users "still see a scary blue warning" ([Indie Hackers](https://www.indiehackers.com/post/we-paid-for-windows-code-signing-and-new-users-still-see-a-scary-blue-warning-d3dab1188f)). Second, it runs only on Windows. Third, its content belongs to museums and Are.na users, so charging for it raises terms questions (Q23). The web app avoids all three. It has no installer, runs on the phone where value checking actually happens, and processes only the user's own images. In absolute terms, though, it is a tip jar, not a business. A typical "good" free-to-paid conversion is 3–5% even in B2B software ([ChartMogul](https://chartmogul.com/reports/saas-conversion-report/)). An art tool competing with seventy free ones should plan on 1–3%. At $8, that is about $800–$2,400 a month from 10,000 monthly users (an inference, not a forecast), and reaching 10,000 users against SEO-built free sites is uncertain. Ads aren't the answer either. Photopea earns about $200K a month mostly from ads, but only at enormous scale ([Indie Hackers](https://www.indiehackers.com/post/making-3m-per-year-with-a-free-product-axW4u1vB6C8f91Z3Lxu5)), and artists punish ads in small tools. Krita is the hopeful precedent: it sells the same GPL code in stores, and store sales "basically now fund [the maintainer] to work full-time" ([Krita 2018](https://krita.org/en/posts/2018/krita-in-the-windows-store-an-update/)). That took a decade of reputation, though.

The wedge is also a technical one, and it explains why this is a separate product rather than a LeMuse feature. LeMuse's desktop value tools (2 to 9 tones, darks/lights isolation, squint, grids) work on streamed museum images because they are **SVG and CSS filters that never read a pixel** ([practice.ts](../app/src/practice.ts)). That is also why LeMuse can never put a number on a value: Cleveland's CDN sends no CORS header, so reading its pixels is blocked. A web app that works only on the user's own photo has full pixel access. It can show a **CIELAB L\* readout (0–100, or a 1–10 step) averaged over a small area**, run an Otsu-chosen notan threshold, and lay a reference and a painting photo side by side **on the same value bands, with the mismatches outlined**. No web rival does the compare, and the native rivals offer only a basic side-by-side ([Painting Mirror](https://apps.apple.com/app/id6769758248); [Value Study Assistant](https://apps.apple.com/us/app/value-study-assistant/id6759689446)). A live-camera version with a "tap the white of your canvas" calibration step would be harder still to copy. Nobody has tested that with users yet, so it belongs in stage 2.

## Stage 1: a static, no-upload app on a subdomain the owner controls

The build reuses what LeMuse already has. Only [api.ts](../app/src/api.ts) imports Tauri, so the React parts are portable, and the repo already enforces the 14-day dependency cooldown, `--ignore-scripts`, the npm audit gate and gitleaks. The plan is an npm workspace in the same public repo. A `packages/value-core` package holds the image maths in pure TypeScript with no DOM, unit-tested. A `web/` folder holds a Vite + React static app on the same pinned versions as `app/`. The maths is standard and cheap. sRGB is decoded to linear and weighted into luminance (Y = 0.2126 R + 0.7152 G + 0.0722 B), then converted to L\* = 116 f(Y) − 16 ([Wikipedia: sRGB](https://en.wikipedia.org/wiki/SRGB); [Wikipedia: CIELAB](https://en.wikipedia.org/wiki/CIELAB_color_space)). That is a 256-entry lookup table per channel. Otsu's threshold comes from one pass over a 256-bin histogram ([Wikipedia: Otsu](https://en.wikipedia.org/wiki/Otsu%27s_method)). Canvas 2D in a Web Worker is enough for photos. WebGPU now ships in every major browser including iOS 26 Safari ([web.dev](https://web.dev/blog/webgpu-supported-major-browsers)), but iOS had a canvas flicker bug until Safari 26.4 ([WebKit 301627](https://bugs.webkit.org/show_bug.cgi?id=301627)), and it would double the test matrix, so leave it out. The real iPhone traps are canvas caps (historically 16.7 megapixels and 384 MB total; [PQINA](https://pqina.nl/blog/canvas-area-exceeds-the-maximum-limit/)) and Safari's inconsistent HEIC handling in file pickers ([WebKit 303803](https://bugs.webkit.org/show_bug.cgi?id=303803)). The app should therefore scale the long edge to 4096 px or less before processing, use `accept="image/*"`, and show a plain "save it as JPEG and try again" when a file won't decode. Current iOS 26 limits still have to be measured on a real device.

Hosting should be **Cloudflare static assets on an account the owner holds**. Static requests there are "free and unlimited" ([Cloudflare](https://developers.cloudflare.com/workers/static-assets/billing-and-limitations)), and a `_headers` file sets the security headers ([Cloudflare headers](https://developers.cloudflare.com/pages/configuration/headers/)). The alternatives fail on terms. Vercel Hobby is "restricted to non-commercial personal use only" ([Vercel](https://vercel.com/docs/plans/hobby)). GitHub Pages may not be used "to run your online business … or SaaS" ([GitHub Docs](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits)), and it can't set response headers; that also answers the old Q18. Netlify's free tier moved to a capped 300 credits a month ([DEV](https://dev.to/devtoolpicks/best-netlify-alternatives-for-indie-hackers-in-2026-ceo)) and stays a fallback. The friend's domain provides a **subdomain by CNAME**, not a path. A subdomain from external DNS works with a plain CNAME ([Cloudflare custom domains](https://developers.cloudflare.com/pages/configuration/custom-domains/)), and it is a separate browser origin. A path would share cookies, storage, the service-worker scope and script access with the friend's site.

The headers are the privacy promise in a form a machine can check. `connect-src 'self'` with no third-party scripts means the browser physically cannot upload the user's photo anywhere. A CI test should assert that the built `_headers` keeps that line, and `_headers` joins the guardrail files the owner must review. Without accounts, cookies, analytics or stored images, the app processes almost no personal data. The host's request logs (IP addresses can be personal data; [CJEU C-582/14](https://curia.europa.eu/juris/liste.jsf?num=C-582/14)) still justify a short privacy notice. No cookie banner is needed while `localStorage` holds settings only. Once money changes hands, a German or Austrian imprint duty arises under §5 DDG ([gesetze-im-internet.de](https://www.gesetze-im-internet.de/ddg/__5.html)). The European Accessibility Act exempts service microenterprises with fewer than 10 staff and €2m or less turnover ([CCPC](https://www.ccpc.ie/business/enforcement/accessibility/european-accessibility-act-guidelines-for-microenterprises/)). Building to WCAG 2.2 AA anyway is cheap.

**Protection** has three layers. The code itself can't be protected: under MIT anyone may rehost the app, and even under AGPL a client-side paywall can be bypassed by anyone who reads the code. So the moat is the name, the domain, the updates and the trust the no-upload promise builds. The supply chain is protected by the controls LeMuse already runs. The **hosting relationship** is the real exposure, because whoever controls DNS can repoint or take down the app. A short written note with the friend should settle five things. The subdomain is dedicated to the app. The owner controls the hosting and the content. The record changes only after 60–90 days' notice, with a redirect on exit. Nothing may be injected (analytics, ads). And the privacy notice says who is who. An owner-held domain can become the canonical name later.

For **payments**, the fixed per-sale fee dominates at these prices. Paddle and Polar both start at 5% + 50¢ ([Checkout Page: Paddle](https://checkoutpage.com/blog/paddle-pricing); [Polar](https://polar.sh/resources/pricing)), which is about 10% of a $10 sale. Gumroad takes 10% + 50¢ plus processing ([Checkout Page: Gumroad](https://checkoutpage.com/blog/gumroad-fees)). Stripe Managed Payments adds 3.5% on top of Stripe's fees ([Stripe](https://support.stripe.com/questions/managed-payments-pricing)), but it delivers no licence keys or files ([Checkout Page](https://checkoutpage.com/docs/articles/migrating-from-lemon-squeezy)). **Lemon Squeezy "is no longer accepting new sign-ups and will shut down on March 31, 2027"** ([Lemon Squeezy](https://www.lemonsqueezy.com/blog/2026-update)). GitHub Sponsors charges no fees on sponsorships from personal accounts ([GitHub Docs](https://docs.github.com/en/sponsors/getting-started-with-github-sponsors/about-github-sponsors)), so it suits the support link. Ko-fi's 2026 fees weren't verified.

## Competitors' best 2026 ideas are keyboard-first and ambient, not AI

The busiest competitor in 2026 is **refern**, a $35 desktop board. Its changelog shows a pattern. Within four months it shipped a full-screen presentation mode on black (v1.10.1, 18 October), an **"I" key that shows the image's details during a timed study** (v1.11.1, 5 November), and a practice calendar with session history and a recap dashboard. It also let users **attach their own work to a calendar day** (v1.6.0 and v1.8.0, August–September), and remembered session settings per workspace ([refern changelog](https://www.refern.app/changelog)). **PureRef 2.0** added a command palette and settings export "to share a setup" ([PureRef blog](https://pureref.com/blog/pureref2/)). **PureRef 2.1** (30 January 2026) added a recent-files overview with pinned favourites and "Arrange randomly" ([PureRef 2.1](https://pureref.com/blog/pureref21/)). The ambient idea has proven demand. **Are.na Frame**, an open-source e-ink display that cycles through a channel, had a hand-built batch that "sold out within hours" ([Are.na newsletter](https://buttondown.com/aredotna/archive/arena-frame-api-updates-event-with-triple-canopy/)). Cosmos users call its full-screen scrolling Canvas "genuinely so useful", and Cosmos offers a toggle to hide AI-generated images ([App Store](https://apps.apple.com/app/id1577975475)). On streaming, searches found **no gesture-drawing OBS overlay at all**, only generic countdown scripts ([OBS forum](https://obsproject.com/forum/resources/pomodoro-timer-with-sound-alerts-2025.2178/)). On the open-source side, **SpeedSketch** (MIT, SvelteKit + Tauri) is LeMuse's closest relative. It has class schedules **with breaks**, plus greyscale, high-contrast and blur filters ([GitHub](https://github.com/AvaLovelace1/speed-sketch)). Oculante's compare mode switches images "while keeping zoom level and position" ([GitHub](https://github.com/woelper/oculante)).

LeMuse already covers more of this than the notes assumed. It has full-screen (`F`), a hidden control bar (`H`), squint as a blur filter, 2–9 value tones and multi-round class plans ([keys.ts](../app/src/keys.ts); [practice.ts](../app/src/practice.ts)). The plans have no breaks, though, and the `I` key is already taken by "values shown", so an info overlay needs a different default key. The other popular features fit badly. Colour and hex search (Cosmos, Pinterest, refern) and visual "find similar" all need image bytes, which breaks the no-pixel-read and no-cache rules. Local CLIP embeddings would mean bulk-downloading topics and shipping a 100 MB–1 GB model, and Apple's MobileCLIP weights are under a research-only licence ([Hugging Face](https://huggingface.co/apple/mobileclip_s0_timm/blob/main/README.md)). 3D posing, video references and collage boards are other product categories.

The 1.1 tray work also gets three checks from the open-source notes. The autostart plugin's `auto-launch` crate "tries the system-wide key first" ([docs.rs](https://docs.rs/auto-launch/latest/auto_launch/)), so confirm an elevated first run can't write HKLM. LocalSend's start-hidden flag failed on Windows when the install path contained spaces, because the `Run` value wasn't quoted ([LocalSend #1293](https://github.com/localsend/localsend/issues/1293)); the 1.1 acceptance test already quotes it. And `tauri-plugin-single-instance` should stop a second launch from opening a second process against the locked catalog while the first hides in the tray. One more check is unverified: when a user turns LeMuse off in Task Manager's startup list, Windows may leave the `Run` value in place, so the settings toggle could still read "on".

## Conclusion

The pixel line now marks the product line. LeMuse streams other people's images and may never read their pixels. That is why its value tools are filters, why it can't show a number, and why charging for it would mean charging around someone else's content. The value app works only on the user's own pixels. That makes it numeric, makes the compare-your-painting feature possible, and makes it the one thing the owner can sell without asking anyone. Shared `value-core` code then flows back the other way: once local folders and "compare with my drawing" exist, the desktop app can show real numbers for files the user owns.

The second insight is about positioning. In 2026 the board apps are racing to add AI search, colour search and visual similarity. LeMuse can't follow, and shouldn't. The ideas it can take are the calm ones: keyboard-first chrome, attribution shown as a feature, a stream as ambient décor, a timer on stream with the creator's name on screen. Together with "museum sources contain no AI images" and "your photo never leaves your phone", these make a coherent identity that the AI-forward rivals can't easily claim. Four facts should be tested before they are relied on, each in minutes. Do the iNaturalist, Auckland and Pexels image hosts load cleanly in a normal browser? What are the iOS 26 canvas limits on a real iPhone? Which patent endpoint returns drawings as images? And does a 1-in-100 visitor really tip? Only that last one needs a launch to answer.
